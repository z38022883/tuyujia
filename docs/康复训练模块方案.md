# 康复训练模块方案（草案 v0.1）

> 状态：草案，待评审
> 关联文档：[2.txt（失语症分级康复方案）](./2.txt)、[失语症患者语言能力评估路径（常辉等，2024）](./失语症患者语言能力评估路径_常辉.pdf)
> 依赖：同学正在开发的「分级评估」模块（本方案与之有明确接口契约，见 §2）

---

## 1. 背景与目标

图语家目前是 AAC 辅助沟通小程序：帮助失语症患者「表达」和「接收」。康复训练模块把产品从「能沟通」延伸到「练恢复」——在分级评估结果的基础上，为患者（及其照护者）生成并执行分级、分维度的居家语言康复训练。

**目标**：

1. 以 docs/2.txt 的分级康复方案为内容骨架（重度 / 中度 / 轻度 × 听理解 / 口语表达 / 读写 / 家庭沟通支持）；
2. 以常辉论文为方法论依据（功能性沟通优先、避免学习效应、及时反馈、量表与测试分开、汉语语料与本土化）；
3. 与分级模块解耦但契约先行：**分级结果是康复方案的输入，康复训练记录是分级效果的输出**，两者闭环。

**非目标（本期）**：不做医学诊断、不做评分量表标准化、不替代言语治疗师；产品定位为「家庭康复训练工具/教育工具」。

## 2. 与分级模块的衔接（关键依赖，契约先行）

同学负责的「分级」模块尚未完成，康复模块必须先定好**接口契约**，两边按契约并行开发。

### 2.1 建议契约：分级结果

```ts
// 分级模块产出 → 康复模块消费（建议由分级同学确认/调整）
interface AssessmentResult {
  assessmentId: string                    // 评估记录 ID
  patientId: string                       // 患者档案 ID（默认 = openid）
  aqScore?: number                        // WAB 失语商（如有）
  severity: 'severe' | 'moderate' | 'mild'
  // 说明：极重度（AQ<26）按 2.txt 并入重度，不再细分
  dimensions?: {
    listening: number                     // 听理解 0-100
    speaking: number                      // 口语表达 0-100
    reading: number                       // 阅读 0-100
    writing: number                       // 书写 0-100
  }
  assessedAt: number
  version: string                         // 评估工具版本，便于后续迁移
}
```

### 2.2 消费方式

| 项 | 方案 |
|---|---|
| 存储 | 云数据库 `rehab_profiles` 集合存「当前生效的 AssessmentResult」，分级模块落库后由康复模块读取（或分级模块直接写该集合） |
| 读取时机 | 进入康复首页时拉取；每次训练开始前校验有效性 |
| 调级 | 分级结果更新（新评估）→ 康复方案自动切换 + 提示「训练方案已按新评估结果调整」 |
| 维度侧重 | 若分级输出 dimensions，训练计划按短板维度加权（如口语表达 40 分 → 口语任务占比提升）；未输出则按等级均分 |

### 2.3 未分级时的降级策略（Phase 1 先行版）

分级模块上线前，康复模块可先行开发并支持：
- **手动选择等级**（进入时引导选择轻/中/重度，可随时更改）；
- 分级上线后自动升级为「读分级结果 → 自动匹配 + 手动可改」。

## 3. 理论依据 → 训练设计原则

### 3.1 内容骨架（docs/2.txt 分级方案）

| 等级 | AQ 范围 | 听理解 | 口语表达 | 读写 | 单次时长 |
|---|---|---|---|---|---|
| 重度 | ≤50（含极重度） | 简单是非应答、实物指认、实物配对 | 口型模仿、序列语（数数 1-10）、音乐哼唱 | 汉字临摹、居家物品贴字认读（不听写） | ≤20 分钟，少量多次 |
| 中度 | 51–75 | 两步连续指令、看图问答、生活常识提问 | 是/否短对话、短句跟读复述、看图描述 | 听写简单短句、文字指令阅读 | 20–30 分钟 |
| 轻度 | 76–93.8 | 多步骤指令、听短文/新闻复述 | 兴趣话题交谈、长句表达、语法完善 | 阅读短文作答、日记书写、段落练习 | 30 分钟，可加难度 |

> 说明：常辉论文给出 WAB 原始分界（76–93.8 轻 / 51–75 中 / 26–50 重 / <26 极重），2.txt 将极重并入重度（≤50），本方案按 2.txt 执行，分级模块如需细分极重，契约里用 severity 主档 + aqScore 保留精度即可。

### 3.2 七条理论 → 题型落点（2.txt 理论支撑节）

| 理论 | 训练设计落点 |
|---|---|
| ① 语义扩散激活 | 词汇分类、图文配对、物品联想题（每题同时刺激类别/用途/颜色等多维语义） |
| ② 词汇层级加工 | 训练阶梯强制「单音 → 字词 → 短句 → 篇章」，题型按阶梯组织，等级决定起点 |
| ③ 公式化语言特殊存储 | 成语朗读、旋律/儿歌哼唱、固定用语提示（「你好」「谢谢」「喝水」等成套表达） |
| ④ 自动化实例 | 生活脚本对话（起床、吃饭、就医、出行）整体演练，不逐字拆解 |
| ⑤ 功能性沟通优先 | **素材全部来自进食/出行/就医/居家高频场景**；语法缺陷不判错，能传意即有效 |
| ⑥ 强制性交互学习 | 语言游戏（如「我说你做」）、陪护-患者轮流问答，限制手势/书写代偿（仅慢性期适用，需陪护监督） |
| ⑦ 多模态感知整合 | 每题尽量「图 + 音 + 字」三通道同时呈现；重度任务强制图文卡 + TTS 范读 |

### 3.3 常辉论文的关键方法论（产品正确性）

| 论文观点 | 模块落地 |
|---|---|
| 学习效应 → 需多套平行任务 | 每题型每等级准备 **≥3 套平行素材**，训练时轮换抽取，避免「背题」假进步 |
| 及时反馈 | 每题作答后立即反馈（对/错 + 语音鼓励），训练结束即时出结果页 |
| 量表 vs 测试性质分开 | 分级 = 测试（同学做）；康复内进度跟踪 = 轻量「进展型」题目，只做相对比较，不做诊断 |
| 天花板效应（轻度测不出） | 轻度等级增加语篇/语用题：看图说故事、短文复述、对话续接、观点表达 |
| 家庭可操作性（常辉：评估可让家属掌握进展） | 训练结果页用「看得懂的进展」（正确率、连续天数、雷达图），面向家属 |
| 汉语本土化 | 全部中文语料 + 中国生活场景；禁用拼音/英文字母类题目（论文指出老年患者识别问题） |

## 4. 功能架构

### 4.1 入口

- **首页功能宫格**新增「康复训练」卡片（`src/pages/home/index.tsx` 的 MODULES 数组加一项，复用现有卡片样式）；
- 「我的」页设置区追加「康复训练」入口（次要入口，便于照护者进入）；
- 分级完成后，分级结果页提供「去康复训练」跳转，形成闭环。

### 4.2 页面

| 页面 | 路径 | 职责 |
|---|---|---|
| 康复首页 | `pages/rehab/index` | 当前等级展示（读分级/手动选择）、今日训练推荐、连续天数、各维度进度概览 |
| 训练执行页 | `pages/rehab/training` | 任务序列渲染：题干（TTS+图+字）→ 作答 → 即时反馈 → 下一题；退出断点续训 |
| 训练结果页 | `pages/rehab/result` | 本轮正确率/时长/维度分布、鼓励文案、分享给家属 |
| 训练记录页 | `pages/rehab/history` | 历史会话列表 + 趋势图（正确率、时长） |
| 家庭支持页 | `pages/rehab/family` | 按等级展示家属沟通指引（短句沟通、放慢语速、安静环境、时长建议等，源自 2.txt 每级「家庭沟通支持」） |

### 4.3 组件复用与新增

**复用**：`PictogramGrid`/`PictogramCard`（图符展示与选择）、`PlaybackOverlay`（TTS 播放态）、`EmptyState`、`services/tts`（朗读题干/范读）、`services/cloud` + `storage`（数据层）、Zustand store 模式。

**新增**：
- `TaskRunner`（任务引擎渲染器：按题型分发到具体答题组件）
- `PickFromPictograms`（听词指认：N 选 1 图符）
- `MatchPair`（图文/图图配对）
- `CategorizeGrid`（词汇分类拖入类目；拖拽参考 movable-view 方案）
- `FollowRead`（跟读复述：范读 → 录音 → 星级自评/陪护评，微信端录音用 `Taro.getRecorderManager`）
- `InstructionCheck`（听指令：陪护确认执行结果 对/错）
- `ScoringBar`（星级/对错反馈）、`ProgressRing`（进度环）

## 5. 任务引擎设计

### 5.1 任务模型

```
训练会话（session）= 计划（plan） = [任务1, 任务2, ...]
任务（task）= 题型（taskType）× 等级（level）× 维度（dimension）× 素材（materials）
```

- 每次会话 3–6 个任务、10–20 分钟；由「今日推荐」按等级 + 短板维度生成，也支持照护者自选任务自由组合；
- 素材轮换：同一任务类型按 `sessionId`/日期做种子随机，命中平行素材组，避免学习效应；
- 作答数据逐题落库：`taskId、题型、维度、作答内容、对错/星级、用时`。

### 5.2 题型库（v1 先做 4 种，占 80% 使用场景）

| 题型 | 等级 | 维度 | 互动形式 | 数据采集 |
|---|---|---|---|---|
| 听词指认 | 重/中 | 听理解 | TTS 读词 → 4 图符选 1 | 对/错、用时 |
| 图文配对 | 重/中 | 听理解+语义 | 词卡 ↔ 图卡两两配对 | 配对正确数、用时 |
| 听指令执行 | 重/中 | 听理解 | TTS 读指令（1~2 步）→ 陪护确认 | 对/错（陪护评） |
| 跟读复述 | 中/轻 | 口语表达 | 范读 → 患者复述 → 星级自评 | 星级、录音可选 |
| 看图描述 | 中/轻 | 口语表达 | 场景图 → 患者描述 → 星级 | 星级、关键词命中可选 |
| 词汇分类 | 中 | 语义 | 图符拖入类目 | 分类正确数 |
| 听短文复述 | 轻 | 听理解 | 短文 → 复述核心 → 要点核对 | 要点命中数 |
| 阅读理解 | 轻 | 读写 | 短文 + 选择题 | 对/错 |
| 汉字临摹 | 重/中 | 读写 | 大字描红（canvas 手写） | 完成度（仅记录，不判分） |
| 成语朗读 | 重/中 | 口语+公式化 | 大字+拼音+TTS 范读 → 跟读 | 星级 |
| 旋律哼唱 | 重 | 口语 | 儿歌播放 → 哼唱（需音频素材，可选） | 无/陪护评 |
| 生活脚本对话 | 中/轻 | 功能性沟通 | 场景脚本轮流问答（陪护参与） | 完成度 |

### 5.3 素材来源

- **优先复用现有图库**：`src/data/seed/pictograms.json` 已覆盖 daily / food / medical / places / actions / objects / time / emotions / quickchat / repair / activities / descriptors 等高频生活分类，与 2.txt「进食、出行、就医高频内容」直接匹配；
- **新增康复语料**（本地 JSON，后续可搬云端）：分级短句库（每级 50+ 句）、短文库（轻度 20+ 篇，多套平行）、成语/儿歌清单、生活脚本场景（10 个场景 × 每场景 1 套问答）；
- 语料文件建议 `src/data/rehab/` 下按 `tasks-{level}.json` 组织，与图库 lexicon 同构，便于评审。

## 6. 数据模型（云开发数据库）

| 集合 | 关键字段 | 说明 |
|---|---|---|
| `rehab_profiles` | openid, severity, aqScore?, dimensions?, sourceAssessmentId, assessedAt, updatedAt | 当前生效的分级结果（契约 §2.1）；可由分级模块写入 |
| `rehab_tasks` | taskType, title, level, dimension, difficulty, materials[], audioUrl?, enabled | 任务库；v1 本地 seed，云端集合为后续运营更新预留 |
| `rehab_sessions` | openid, profileId, planId?, startedAt, finishedAt, durationSec, tasks[{taskType, level, dimension, correct?, rating?, durationSec}], overallCorrectRate | 训练记录，一次会话一条 |
| `rehab_progress` | openid, date, sessionCount, durationSec, perDimension{listening/speaking/reading/writing:{count, correctRate}} | 日聚合，趋势图数据源 |

- 云函数：`saveRehabSession` / `getRehabSessions` / `getRehabProgress` / `updateRehabProfile`（复用现有 `services/cloud` 的 `callFunction` 封装与 login 鉴权）；
- 本地缓存：`rehab_profile`、最近 N 条 sessions 缓存到 storage，弱网可离线训练后补传。

## 7. 实施分期（重点：分级完成前的先行工作）

> 总原则：**框架先行、内容等分级**。Phase 1 不依赖分级模块即可完整跑通「训练闭环」；分级完成后 Phase 2 填充三级详细内容。

### Phase 0 — 对齐（本周，半天~1天）
- [ ] 评审本方案；
- [ ] 与分级同学确认 §2.1 契约（AssessmentResult 字段、落库位置）；
- [ ] 确认微信端 TTS 方案（见风险 §9），建议立即小范围验证腾讯云智能语音插件可用性。

### Phase 1 — 康复框架（分级完成前可并行，约 1–2 周，单人）
- [ ] 首页入口 + `pages/rehab/index`（等级展示/手动选择、今日推荐、进度概览骨架）；
- [ ] 任务引擎 `TaskRunner` + 4 种核心题型（听词指认、图文配对、听指令、跟读复述）；
- [ ] 训练执行页 / 结果页，断点续训；
- [ ] 内置 1 级完整任务库（以「中度」为默认档），本地 seed 数据；
- [ ] 训练记录本地 storage 落库（云端同步放 Phase 2）；
- [ ] 接入分级接口（未分级走手动选择，分级后自动读取）。

**验收**：新用户 3 步内进入训练；能完整跑完一次会话并出结果页；中途退出可续训；手动选级生效。

### Phase 2 — 分级康复内容（分级完成后，约 2–3 周）
- [ ] 按「3 级 × 4 维度」铺全题库：重度 ≥60 题、中度 ≥80 题、轻度 ≥80 题，**每题型 ≥3 套平行素材**；
- [ ] 剩余题型补齐（词汇分类、看图描述、听短文复述、阅读理解、汉字临摹、成语朗读、生活脚本对话、旋律哼唱可选）；
- [ ] 分级结果 → 自动匹配训练方案 + 调级提醒 + 维度加权；
- [ ] `pages/rehab/family` 家庭支持页（每级家属指引，源自 2.txt）；
- [ ] sessions/progress 云端同步 + 云函数 + 历史页趋势图。

**验收**：分级结果正确映射训练方案；题库覆盖矩阵（等级×维度×题型）无空白；两条平行素材轮换可见。

### Phase 3 — 数据与自适应（二期，约 1–2 周）
- [ ] 训练趋势统计（正确率/时长/连续天数/雷达图），面向家属「看得懂的进展」；
- [ ] 难度自适应：正确率连续达标 → 下一轮难度微调 / 升级建议（提示重新评估）；
- [ ] 训练提醒（订阅消息）、分享训练报告给家属/治疗师；
- [ ] 探索 ASR 语音识别自动评分（需调研微信同声传译/腾讯云 ASR 成本与合规）。

## 9. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| **微信端 TTS 未落地**（现为 toast 兜底） | 康复训练重度依赖语音，听理解/跟读类题型全部受影响 | Phase 0 验证腾讯云智能语音插件（方案 A）；服务端合成 MP3 兜底（方案 B，见迁徙方案 §3.2）；跟读题降级为「陪护朗读」模式 |
| 分级模块延期 | Phase 2 内容无法铺开 | 手动选级先行，Phase 1 不阻塞 |
| 契约返工 | 接口对不上 | Phase 0 先定契约；康复侧所有字段读取做容错默认值 |
| 医疗合规 | 被认定为医疗器械 | 定位「教育/训练工具」，文案避免诊疗用语；训练数据仅本人/家属可见 |
| 包体积（主包 ≤2MB） | 语料+组件超限 | 语料 JSON 控制在 ~100KB 内，超限走云函数拉取；图片全 CDN |
| 重度患者操作能力 | 无法点按答题 | 陪护辅助模式（陪护代操作/确认）；任务全部支持「陪护确认」交互 |
| 素材质量/版权 | 语料不规范 | 素材复用现有图库；文字语料内部评审；儿歌/音频需授权 |
| 隐私（健康数据） | 康复记录属敏感数据 | 仅存 openid 维度数据；隐私政策补充说明；不上传录音（录音仅本地，可选） |
