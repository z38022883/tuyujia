# 患者程度自选与功能适配方案（v0.2）

> **v0.2 变更说明**：推翻 v0.1"首页改造成主沟通界面"的取向——**首页保留现有功能卡片不动**（不是每次打开都要先说）。
> 程度（轻/中/重）改为作用于两大主要功能 **说（表达）**、**听（接收）** 和一项重要功能 **康复（训练）** 的**内容与展示形式**。
> 状态：2026-09-01 待评审。

---

## 1. 背景与结论

- 产品：失语症患者的图片沟通小程序。首页 = 功能卡片导航（表达/接收/康复训练/收藏/历史），患者/照护者按需进入。
- 需求：不等同事的分级评估，先由**照护者/治疗师勾选 轻/中/重** 建档；程度不改变首页结构，而是决定：
  1. **说（表达页）**：词板的词量、图块大小与点词交互 —— 轻=全量（现状），中=12~16 常用词 + 简易句条，重=6 个超大词、单点读整句；
  2. **听（接收页）**：编辑流程是照护者工具**保持不变**；只有"**展示给患者**"环节按程度裁剪内容与放大呈现；
  3. **康复（训练）**：训练等级 = 档案程度（去掉手动双轨）；题库按等级分级（内容），TaskRunner 预留按等级展示形式参数。
- 收藏 / 历史等数据页面不受程度影响。

## 2. 总体流程

```
首次启动（无档案）
  └─ 首页 onShow 首检：无 severity → reLaunch「程度选择页」→ 选轻/中/重 → 建档 → 回首页
日常启动（有档案）
  └─ 首页 = 功能卡片（不变，仅头部多一个"程度徽标"，点它可改档）
       ├─ 表达页（说）→ 按程度：词板词量/图块/句条交互
       ├─ 接收页（听）→ 编辑流程不变；"展示给患者"画面按程度
       └─ 康复训练页 → 等级默认 = 档案程度
修改程度：首页徽标 或 我的→程度设置 → 程度页（预选当前值）→ 保存回首页
```

## 3. 程度对「说」——表达页的适配

### 3.1 规格

| 维度 | 轻 mild | 中 moderate | 重 severe |
| --- | --- | --- | --- |
| 首屏词板 | 现状 root 板（策展词+分类文件夹+常用，全量可翻） | 16 个常用词大网格（核心 8 + 扩展 8） | 6 个超大图块（吃/喝/去/厕所/帮/疼） |
| 图块尺寸 | 现状紧凑卡 | 大卡（4×4） | 超大卡（2×3，占满可视区） |
| 点词 | 进句条 → 生成候选句 → 播放（现状全流程） | 进句条 → **说 = 按序直接连读**（免候选句选择） | 点一下 = 朗读**预设整句**（无句条） |
| 句条 | 完整（候选/收藏） | 简易（≤4 词、点条目可移除、清空） | 无 |
| 更多词 | 分类文件夹随便进 | 顶部「更多词」→ 完整图库（进现有全量板，可用候选句） | 不提供（换词=去我的改档；隐藏入口见 §10-4） |

### 3.2 重度（severe）6 词表（集中在 `src/data/boards.ts` 一处，词/句均可改）

| 展示词 | 图符 id | 点击朗读整句 |
| --- | --- | --- |
| 吃 | `p_eat` | 我要吃饭 |
| 喝 | `p_drink` | 我要喝水 |
| 去 | `p_go` | 我要出去 |
| 厕所 | `p_toilet` | 我要上厕所 |
| 帮 | `p_help_me` | 请帮帮我 |
| 疼 | `p_pain` | 我疼 |

点词 → `useAppStore.speakSentence(整句, [id])`：播放浮层 + 朗读 + 记入表达历史（与现有链路同源）。
加载时按 id 查图符，缺失自动跳过并 console.warn。

### 3.3 中度 16 词初版（核心 8 + 扩展 8，名单可换）

我 `p_i`｜你 `p_you`｜要 `p_want`｜不想 `p_dont_want`｜去 `p_go`｜来 `p_come`｜吃 `p_eat`｜喝 `p_drink`
厕所 `p_toilet`｜疼 `p_pain`｜帮 `p_help_me`｜谢谢 `p_thank_you`｜好 `p_good`｜水 `p_water`｜是 `p_yes_response`｜等 `p_wait`

- v1 组句 = 按点击顺序**直接连读**（"我 要 厕所"→ 读"我要厕所"）；自然成句的组合模板表（如 `我+要+厕所→我要上厕所`）作为后续优化，`boards.ts` 预留字段。
- 实现要点：`PictogramGrid` 按档案程度决定 root 内容源与卡片尺寸（轻=现状板 / 中=16 词+「更多词」入口 / 重=6 词、不渲染文件夹）；`SelectionTray` 按程度切换"说"的行为（轻=生成候选 / 中=直接连读 / 重=整页不渲染句条）；`PictogramCard` 增加尺寸档位（默认 / lg / xl）。

## 4. 程度对「听」——接收页的适配

- **编辑/换图/排序阶段**：照护者工具，三档完全一致，不改。
- **「展示给患者」大屏（displayOverlay）** 按程度：

| 维度 | 轻 mild | 中 moderate | 重 severe |
| --- | --- | --- | --- |
| 文字 | 整句原文大字 | 原文小字（辅助） | 不显示原文 |
| 图符 | 现状：逐词卡片序列 | 只显示**匹配到的内容词**，大卡（去掉未匹配项/小字标签） | **1 个核心词超大图** + 其余内容词缩略横排（可点听） |
| 点图 | 无 | 点图=读该词 | 点图=读该词 |
| 回答能力 | 无 | 无 | 底部大号「是 / 不是」回答钮（点即读） |
| 操作 | 重播/完成（现状） | 重播/完成 | 重播/完成 |

- **核心词选取规则 v1**（`src/utils/severity-display.ts`）：对已匹配 token 依次按 ① 命中重级 6 词 ② 图符分类 ∈ {medical, food, places, actions, daily} ③ 词长最长 取首个；句子含多个内容词时其余词按原序缩略展示。
- 中度"内容词过滤"：保留全部**匹配成功**的 token（未匹配项只在照护者编辑阶段提示，不进入展示）。

## 5. 程度对「康复」的适配

- **等级来源统一**：康复训练等级 = 档案程度（severe/moderate/mild 同枚举，直接复用现有 rehab 等级体系）；rehab 首页现手动 chips 与档案**双向同步**（改任一即改档案），消除两套程度。
- **内容分级**：题库按「等级 × 维度」填充（沿用康复训练模块方案 §5 架构，`TASK_LIBRARY` 仍空，分级内容后续按档案程度生成任务）。
- **展示形式分级（预留）**：TaskRunner/题卡增加按等级展示参数（重=更大字号/更少干扰/更强提示；轻=标准/丰富），随题库落地时启用，本期只定义参数接口。

## 6. 程度选择页与档案

- 新页 `pages/level/index`：标题"选择使用程度"；副文案"请照护者根据患者目前情况选择，可随时修改"。
  3 张大卡：轻 🟢（能说短句、听懂大部分日常 → 完整图库+完整表达）、中 🟠（想说常卡壳、能认图 → 16 个常用词）、重 🔴（几乎无法开口 → 6 个最刚需词，点一下说整句）。
  页脚："仅用于界面适配，不代表正式医学评估"；确认按钮未选中置灰；保存 → `reLaunch` 回首页。
- 档案：`src/types/profile.ts` `PatientSeverity`（复用 rehab 枚举值）+ `PatientProfile{severity, updatedAt, severitySource:'self'|'assess'}`（assess 字段为同事分级预留）。
- 存储：`src/store/useProfileStore.ts`，key `tuyujia_patient_profile`；`src/app.tsx` 启动加载。
- 入口：① 首页头部「程度徽标」小 chip（轻/中/重 标签，点进程度页）；② 我的页「程度设置」行。首启门禁 = 首页 onShow 首检 reLaunch（避免 appLaunch 时序/tabBar 闪跳）。

## 8. 实施阶段

- **P0 对齐**：本文档评审（进行中）。
- **P1 档案与勾选**：types / storage / profile store / 程度页 / 首页徽标 / 我的入口 / rehab 等级同步 / 首页首检门禁。
- **P2 「说」适配**：PictogramCard 尺寸档 → PictogramGrid 程度化 root（16 词板 + 更多词入口、6 词板）→ SelectionTray 行为分档 → 表达页重度/中度布局。
- **P3 「听」适配**：severity-display 规则 → receive 展示大屏三档（含重度 是/不是 回答钮）。
- **P4 数据与打磨**：词表/整句文案校准、空数据兜底、切档即时生效（重置板/句条）、样式走查、TaskRunner 展示参数接口（随题库启用）。
- **P5 后续（不在本期）**：中度组合模板自然成句、重级隐藏"更多词"照护者入口、推荐/自定制词板、分级评估结果覆盖档案、TTS 真机方案。

## 9. 风险与注意

- 新增页面后需**清 DevTools 缓存**再编译（此前 rehab 页同款坑）。
- 重度表达页无文件夹/无句条属刻意设计；误操作回退 = 我的页改档，需在程度页文案讲清。
- TTS：小程序端现仅 toast 兜底、无真实语音；"点一下读整句/是/不是"依赖 TTS 落地，目前播放浮层照常出文字。
- 中度直接连读成句可能生硬，模板表优化见 P5，避免本期阻塞。
- 老用户无档案：升级后首次进首页先到程度页，属预期。
