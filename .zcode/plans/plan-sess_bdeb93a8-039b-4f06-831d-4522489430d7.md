# 图语家真机卡顿 + 语音首次响应慢优化

## Context（诊断结论）

**首次语音慢的根因**（`src/services/tts.ts:106`）：微信端每次朗读都串行走「云函数 textToSpeech（首次含冷启动）→ 腾讯云 TTS 合成 → base64 mp3 回传 → 写临时文件 → 新建播放器」，且**从不缓存**——同一句话说十次就完整走十遍全流程，首次 2~5 秒。

**真机卡顿的根因**：
1. 当前 dist 是**未压缩 dev 构建**（app.js 可读、带 .map）——若真机预览用的是 `pnpm dev:weapp` 产物，天然比生产构建卡（需改用 `build:weapp`，会在交付说明强调）。
2. 启动即同步解析 ~190K 康复题库 JSON：`app.tsx` → `useRehabStore` → `@/data/rehab` → `tasks.generated.json`(120K) + `tasks.manual.json`(68K)，低端机明显拖慢首屏。
3. 全部 19 个页面打进主包（dist 3.2M，无分包、无 `lazyCodeLoading`）。
4. 词板网格无 memo：`PictogramGrid` 里 `resolveSevereWords()` 每次 render 重算、返回新数组导致 `useMemo` 失效，`PictogramCard` 未 memo。

已验证的依赖边界（分包可行性）：`useTcmStore`/`data/tcm` 仅 tcm 页面引用；`TaskRunner`/`components/rehab` 仅 rehab 页面引用；主包侧 home/mine 只用 `REHAB_LEVEL_MAP` 元信息；`streak-days.ts` 是独立工具（仅注释提及 tcm）。可以安全分包。

## 改动

### A. 语音提速（核心诉求）
1. **`src/services/tts.ts` 重构播放通道**：新增本地 LRU 音频缓存
   - 缓存目录 `${USER_DATA_PATH}/tts-cache/`，文件名 = `t_${hash}.${ext}`（hash 为 `voiceName|rate|text` 的 djb2 + 文本长度，碰撞概率可忽略）
   - 索引存 storage（`{hash: {file, size, usedAt}}`），预算 64 条 / 8MB，超限 LRU 删除文件+索引
   - `speakWithCloud`：命中缓存 → 直接播（<100ms）；未命中 → 合成后写入缓存路径（替代现临时文件，播放结束不再删除）
   - `stopPlayback` 打断时缓存文件保留
2. **`prewarmTts()` 导出**：后台顺序预合成重度预设句（`@/data/boards` 的 `SEVERE_EXPRESS_WORDS` 中带 `phrase` 的约 6-8 条）并写缓存，同时顺带预热云函数容器冷启动；失败静默。后台流量约 <0.5MB/次启动。
3. **`src/app.tsx`**：weapp 端启动 4 秒后调用 `prewarmTts()`（setTimeout，不阻塞启动/首屏）。

### B. 启动与渲染减负
4. **`src/app.config.ts`**：加 `lazyCodeLoading: 'requiredComponents'`；新增 `subPackages`：`pages/rehab`（5 页）、`pages/assessment`（1 页）、`pages/tcm`（4 页）；主包 pages 列表相应移除（tabBar 的 home/mine 留主包，页面跳转 URL 不变）。
5. **拆分 `src/data/rehab`**：新建 `src/data/rehab-meta.ts`，迁出无 JSON 依赖的元信息（`REHAB_LEVELS`、`REHAB_LEVEL_MAP`、`REHAB_DIMENSION_LABELS`、`REHAB_TASK_TYPE_LABELS`、`REHAB_FAMILY_GUIDES`、`getRehabLevelMeta`）；`data/rehab/index.ts` 改为 re-export 这些 + 保留题库逻辑。`home/index.tsx`、`mine/index.tsx`、`assessment/entry/index.tsx` 改 import `@/data/rehab-meta`。
6. **`src/store/useRehabStore.ts`**：顶部静态 `import { buildRehabTasks }` 改为 `startSession` action 内 `require('@/data/rehab')` 懒加载（webpack 惰性执行，188K JSON 解析推迟到首次开始训练，而非 app 启动）。已知取舍：同步 require 仍使其留在主包体积内，但启动不再解析。
7. **`config/index.ts`**：`mini.optimizeMainPackage: { enable: true }`（tcm 数据/store、TaskRunner、rehab 题库组件等仅分包引用的模块自动移出主包）。
8. **词板渲染 memo**（`src/components/PictogramGrid/index.tsx`）：`adaptiveWords` 用 `useMemo`（依赖 adaptive/severity）；`handleSelect` 用 `useCallback`；`src/components/PictogramCard/index.tsx`、`FolderTile/index.tsx` 包 `React.memo`（纯展示组件）。

### C. 构建配置
9. `config/index.ts`：`cache.enable: true`（构建提速）。
10. `project.config.json`：`uploadWithSourceMap: false`、`minified: true`。

## 验证
- `pnpm typecheck` + `pnpm lint` 通过
- `pnpm build:weapp` 成功；检查 `dist/app.json` 含 `subPackages` + `lazyCodeLoading`；对比主包体积（rehab/tcm JS 落入分包目录，主包应减少 ~700K+）
- 人工真机验证（用生产构建预览）：词板点选/切板流畅度；同一句第二次朗读应即时出声；杀进程重启后缓存仍命中；重度词板首次点击响应明显加快
